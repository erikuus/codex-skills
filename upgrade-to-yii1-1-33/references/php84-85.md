# PHP 8.4 and 8.5 migration audit

Checked against official documentation on 2026-10-23. These are prioritized Yii-app checks, not exhaustive release notes. Follow linked guides for extensions actually used. New language features are optional; this upgrade does not require adopting them.

## PHP 8.4 deprecations that remain relevant on 8.5

- Make typed parameters with `= null` explicitly nullable; check required parameters following them.
- Replace `trigger_error(..., E_USER_ERROR)` deliberately; remove obsolete `E_STRICT` references.
- Replace callback-list `session_set_save_handler()` with its object form. Audit deprecated session ID/trans-SID settings and `SID`.
- Pass CSV escape arguments explicitly, including SplFileObject defaults. Preserve the existing dialect before choosing empty escape.
- Audit one-argument `ReflectionMethod`, two-argument `stream_context_set_option`, `xml_set_object`, and non-callable XML handlers.
- Review PDO_PGSQL dollar-quoted `??`, two-argument pgsql fetch APIs, obsolete MySQLi ping/kill/refresh, and affected Intl overloads.

Source: [PHP 8.4 deprecations](https://www.php.net/manual/en/migration84.deprecated.php).

## PHP 8.4 behavior changes

- `exit`/`die` use stricter argument handling: test termination/error paths.
- GD encoders and several Intl/mbstring/XML functions throw errors for invalid arguments; test malformed uploads and input.
- DBA/ODBC resources become objects; SOAP internal resources also change. Review `is_resource` against each API's failure contract.
- PDO_PGSQL DSN credentials now override constructor credentials. Inspect conflicting configuration without printing secrets.
- Some PDO attributes become booleans. Test strict comparisons and connection setup.
- PCRE2 10.44 recognizes `{,n}` quantifiers and changes some Unicode character classes; test validators.
- Temporary filenames grow; check fixed-width storage assumptions. JIT defaults change; review explicit tuning if used.

Source: [PHP 8.4 incompatibilities](https://www.php.net/manual/en/migration84.incompatible.php).

## New PHP 8.5 deprecations

- Replace casts `(boolean)/(integer)/(double)/(binary)` with `(bool)/(int)/(float)/(string)` in code, not strings or schema types.
- Review null array keys, including `array_key_exists`; reject/skip/normalize according to semantics.
- Remove obsolete `curl_close`, `curl_share_close`, `finfo_close`, `imagedestroy`, `xml_parser_free`; retain actual I/O closes.
- Update driver-specific `PDO::*` constants/methods, not generic PDO APIs.
- Review reflection `setAccessible`, SplObjectStorage attach/detach/contains, ArrayObject/ArrayIterator wrapping objects, and `$http_response_header`.
- Audit backticks, semicolon-terminated switch labels, nonnumeric string increments, null `__debugInfo`, and output inside output handlers.
- Check `chr` range, `ord` byte length, implicit directory handles, `socket_set_timeout`, `mysqli_execute`, and affected INI settings.
- `__sleep`/`__wakeup` are **soft-deprecated**: do not rewrite persisted serialization casually or describe them as removed.

Source: [PHP 8.5 deprecations](https://www.php.net/manual/en/migration85.deprecated.php).

## PHP 8.5 behavior and configuration changes

- OPcache is built in; remove obsolete `zend_extension=opcache.so`/DLL loading directives from 8.5 configuration. Enable flags still apply.
- Destructuring non-arrays except null now warns. Check DB/API results returning false before `list()` or array destructuring.
- Out-of-range float-to-int casts and NAN casts warn; exercise large IDs, totals and imports.
- PDO fetch-class constructor arguments follow named/reference argument rules; some fetch flags change numeric values. Use constants and test custom hydration.
- Compilation/class-linking error handling changes; test autoload/bootstrap failures and logging.
- Check `Collator::SORT_REGULAR` numeric-string ordering, affected Intl/LDAP argument errors, and removed `disable_classes` configuration where used.

Source: [PHP 8.5 incompatibilities](https://www.php.net/manual/en/migration85.incompatible.php).

## Yii-specific implementation decisions

### PDO migration is more than renaming a method

The target's `CDbConnection::createPdoInstance()` constructs its `pdoClass`, normally `PDO`; it does not automatically call `PDO::connect()`. Renaming a driver-specific method requires a compatible connection object. Inspect actual object classes and app adapter/subclass overrides first. For PHP 8.4/8.5-only apps, a suitable driver-specific `pdoClass` or narrow app connection override may fit; verify driver selection, attributes, transactions and SQL Server adapters. Do not change connections using only generic PDO operations.

`PDO::connect()` was added in 8.4 and can return a driver-specific subclass. [Official documentation](https://www.php.net/manual/en/pdo.connect.php).

### Preserve behavior

- A null user ID may denote a guest. Do not normalize it into a privileged identity; test both guest and authenticated RBAC paths.
- Preserve empty-string key semantics only where intended. Otherwise reject invalid IDs or skip missing records.
- Decide whether nullable filters preserve null or produce empty strings; indiscriminate string casts change that contract.
- Test CSV quotes, backslashes, delimiters, multiline fields and empty values before changing escaping.
- Do not globally remove `close()` methods by name. Streams, sockets and transactions still have meaningful lifecycles.
- Keep dependency upgrades scoped and pinned. Vendor scanner hits identify package-level issues; prefer a compatible release over editing installed Composer packages.

Capture deprecations during lint/compilation as well as runtime. Regex scans miss multiline declarations, dynamic calls and data-dependent keys. Zero hits do not establish compatibility.
