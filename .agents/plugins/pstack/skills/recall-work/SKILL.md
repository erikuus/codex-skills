# Recall work

Identify the project, topic and time window from the request. For “recent” start with the previous seven days and report the window. Follow an explicit chat reference directly. If the user supplied a sufficiently detailed handoff, use it and check the live state.

In Codex desktop use the available chat-list and chat-read tools. Filter candidates by project or checkout, date and topic before opening relevant sections. Limit the search to the requested scope. When chat history is unavailable, reconstruct from the supplied handoff, repository and linked records, and say which source you lacked.

Extract decisions, revisions, outstanding questions, reversions, and concrete artifacts. Check the worktree, branch, commits and relevant diffs. A branch title or old chat claim alone cannot establish what landed. Resolve a relevant PR or issue with the available connector when it affects the answer. Operational claims follow the project's current status procedure; record unknown when its authoritative check cannot be reached.

Return a compact handoff: where work stopped, what is present now, which decisions or blockers remain, and the next concrete action. Cite chats for prior intent and current artifacts for present state. Respect the distinction between a request for recall and one to continue implementing.
