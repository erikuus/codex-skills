# Settle a design question

Name the decision and an observation that could change it. A consumer reading a representative export can expose a missing identifier. Real browser interaction can settle a focus or layout question.

Build the smallest disposable probe that exercises the disputed boundary. Keep it separate from production paths. For alternatives, use the same representative input or interaction; a switcher helps for visual variants. Use the actual rendering engine, database, or protocol where its behavior is what you need to learn.

Record what each variant did, which constraint decided the choice and what the probe left untested. Keep a screenshot, output, or timing only when it supports that decision. Treat prototype code as disposable. For a stakeholder decision, use the project's established acceptance workflow.
